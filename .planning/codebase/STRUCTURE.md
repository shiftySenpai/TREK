## Directory Purposes

**client/**
- Purpose: React single-page application (SPA) served to users
- Contains: Pages, components, state stores (Zustand), API client, custom hooks, styles, offline DB, sync logic
- Build output: `client/dist/` (committed to server as static assets)
- Package manager: npm (workspace)

**server/**
- Purpose: NestJS backend API and WebSocket server
- Contains: NestJS controllers and services, database layer, middleware, utilities, scheduled tasks, MCP integration
- Database: SQLite at `server/data/travel.db` (created at runtime)
- Logs: `server/data/logs/trek.log` (created at runtime)
- Package manager: npm (workspace)

**shared/**
- Purpose: Shared TypeScript package with API contracts (Zod schemas)
- Contains: One folder per domain (trip, place, assignment, day, etc.) with `.schema.ts` files
- Consumed by: Both server (validation) and client (type inference)
- No runtime logic; types and schemas only
- Package manager: npm (workspace)

**plugin-sdk/**
- Purpose: SDK for third-party plugin development
- Contains: Plugin interfaces, example plugins, build tools
- Package manager: npm (workspace)

**scripts/**
- Purpose: Utility scripts for development and operations
- Contains: Database scripts, migration helpers, export/import tools
- Examples: `scripts/seed-demo.sh`, `scripts/backup-db.sh` (if present)

**docs/**
- Purpose: Project documentation (API docs, configuration, deployment)
- Contains: Markdown files, architecture diagrams, setup guides

**.planning/codebase/**
- Purpose: GSD-generated codebase analysis documents
- Contains: ARCHITECTURE.md, STRUCTURE.md, STACK.md, CONVENTIONS.md, etc.
- Generated by: `/gsd-map-codebase` command

## Key File Locations

**Entry Points:**

| Purpose | File | Notes |
|---------|------|-------|
| Server startup | `server/src/index.ts` | Initializes directories, starts NestJS app, scheduler, WebSocket |
| Server bootstrap | `server/src/bootstrap.ts` | Builds NestJS app; shared with integration test harness |
| Server app module | `server/src/nest/app.module.ts` | Root NestJS module; imports all domain modules |
| Client root | `client/src/main.tsx` | Mounts React app to DOM; initializes connectivity probe |
| Client app | `client/src/App.tsx` | Root component; routing, auth guards, theme setup |

**Configuration:**

| Purpose | File | Scope |
|---------|------|-------|
| Server config | `server/src/config.ts` | Env vars, app settings, feature flags |
| Client TypeScript | `client/tsconfig.json` | Path aliases, strict mode, module resolution |
| Shared TypeScript | `shared/tsconfig.json` | Library compilation config |
| Database schema | `server/src/db/schema.ts` | SQL table definitions, constraints |
| Database migrations | `server/src/db/migrations.ts` | Schema evolution (timestamps, backwards-compatible) |

**Core Logic:**

| Purpose | Files | Pattern |
|---------|-------|---------|
| Trip domain | `server/src/nest/trips/`, `shared/src/trip/` | Controller → Service → Database; Zod schemas in shared |
| Place domain | `server/src/nest/places/`, `shared/src/place/` | Same pattern |
| Assignment domain | `server/src/nest/assignments/`, `shared/src/assignment/` | Same pattern |
| Auth | `server/src/nest/auth/`, `shared/src/auth/` | JWT + MFA; ephemeral token for WebSocket |
| Client state | `client/src/store/*.ts` | Zustand stores; one per major domain |
| Client API | `client/src/api/client.ts` | Axios instance with error handling, idempotency headers |
| Client sync | `client/src/sync/tripSyncManager.ts` | Background sync, retry logic, offline queue |
| WebSocket | `server/src/websocket.ts` | Room-based broadcasts, rate limiting, auth |

**Testing:**

| Purpose | Location | Pattern |
|---------|----------|---------|
| Server unit tests | `server/src/**/*.test.ts` | Vitest + NestJS testing utilities |
| Server E2E tests | `server/tests/` (if present) | Playwright or similar |
| Client unit tests | `client/src/**/*.test.tsx` | Vitest + @testing-library/react |
| Shared tests | `shared/src/**/*.test.ts` | Schema validation tests |

## Naming Conventions

**Files:**

- **Controllers:** `{domain}.controller.ts` (e.g., `trips.controller.ts`, `places.controller.ts`)
- **Services:** `{domain}.service.ts` (e.g., `trips.service.ts`, `places.service.ts`)
- **Modules:** `{domain}.module.ts` (e.g., `trips.module.ts`)
- **Guards:** `{name}.guard.ts` (e.g., `jwt-auth.guard.ts`, `trip-access.guard.ts`)
- **Schemas:** `{domain}.schema.ts` (Zod; e.g., `trip.schema.ts`, `place.schema.ts`)
- **Stores:** `{domain}Store.ts` (Zustand; e.g., `authStore.ts`, `tripStore.ts`)
- **Hooks:** `use{Name}.ts` (React custom hooks; e.g., `useAuthCheck.ts`, `useTripData.ts`)
- **Pages:** `{Name}Page.tsx` (e.g., `TripPlannerPage.tsx`, `DashboardPage.tsx`)
- **Components:** `{Name}.tsx` (PascalCase; e.g., `TripCard.tsx`, `DayPlanner.tsx`)
- **Utils:** `{name}.ts` (e.g., `formatDate.ts`, `calculateDistance.ts`)
- **Tests:** `{file}.test.ts` or `{file}.test.tsx` (co-located with source)

**Directories:**

- **Domain modules:** `{domain}` (lowercase, e.g., `trips`, `places`, `assignments`)
- **Component directories:** `{Domain}` (PascalCase, e.g., `TripCard`, `DayPlanner`)
- **Store directory:** `store/` (one directory, multiple files)
- **API directory:** `api/` (grouped HTTP + WebSocket)
- **Utilities:** `utils/` (all helpers in one place)
- **Hooks:** `hooks/` (all custom hooks)

## Where to Add New Code

**New Feature (e.g., new trip attribute "weather alerts"):**

1. **Add schema** → `shared/src/{domain}/{domain}.schema.ts`
   - Define Zod shape for the new field
   - Export as `TripWeatherAlertsCreateRequest`, `TripWeatherAlertsUpdateRequest`

2. **Migrate database** → `server/src/db/migrations.ts`
   - Add timestamped migration adding column to trips table
   - Use `db.exec()` for DDL; always backwards-compatible

3. **Create service** → `server/src/nest/{domain}/{domain}.service.ts`
   - Add method `updateWeatherAlerts(tripId, userId, alerts)`
   - Validate ownership, update database, return result

4. **Add controller route** → `server/src/nest/{domain}/{domain}.controller.ts`
   - Add `@Put('/alerts')` route using schema-validated body and DTO
   - Call service, return response using response envelope

5. **Publish WebSocket event** → Call `broadcast(tripId, 'trip:weatherAlerts:updated', { alerts })` in service

6. **Create client store** → Update `client/src/store/tripStore.ts` or create new `client/src/store/weatherStore.ts`
   - Add state slice with new field
   - Add mutation function that calls API and syncs on WebSocket event

7. **Create UI** → `client/src/components/TripSettings/WeatherAlerts.tsx`
   - Read from store
   - Call mutation on change
   - Display loading/error states

8. **Add tests** → Alongside each layer
   - Schema: `shared/src/{domain}/{domain}.schema.test.ts`
   - Service: `server/src/nest/{domain}/{domain}.service.test.ts`
   - Controller: `server/src/nest/{domain}/{domain}.controller.test.ts`
   - Component: `client/src/components/TripSettings/WeatherAlerts.test.tsx`

**New Component/Module:**

1. Create directory: `client/src/components/{ModuleName}/`
2. Create main component: `client/src/components/{ModuleName}/{ModuleName}.tsx`
3. Export from barrel file: `client/src/components/{ModuleName}/index.ts`
4. Import in parent page: `import {ModuleName} from '../components/{ModuleName}'`
5. Add test: `client/src/components/{ModuleName}/{ModuleName}.test.tsx`

**Utilities:**

- **Shared utilities (used by both server and client):** `shared/src/common/`
  - Example: `sanitize.ts` (sanitization helpers)
- **Server-only utilities:** `server/src/utils/`
  - Example: `formatDate.ts`, `calculateDistance.ts`
- **Client-only utilities:** `client/src/utils/`
  - Example: `formatCurrency.ts`, `parseLocation.ts`

## Special Directories

**server/data/**
- Purpose: Runtime-generated directories for database, logs, uploads
- Generated: Yes (created at startup if missing)
- Committed: No (in `.gitignore`)
- Subdirs: `backups/`, `logs/`, `tmp/`, `travel.db`

**server/uploads/**
- Purpose: User-uploaded files (covers, photos, avatars, exports)
- Generated: Yes (created at startup)
- Committed: No (in `.gitignore`)
- Subdirs: `covers/`, `photos/`, `files/`, `avatars/`

**client/dist/**
- Purpose: Built SPA (production bundle)
- Generated: Yes (by `npm run build`)
- Committed: No (in `.gitignore` or build artifact)
- Served by: Server at root path `/` (index.html fallback)

**shared/dist/**
- Purpose: Compiled @trek/shared package
- Generated: Yes (by `npm run build`)
- Committed: No (in `.gitignore`)
- Consumed by: Both server and client (npm symlink in workspace)

**node_modules/**
- Purpose: npm dependencies for all workspaces
- Committed: No (root-level; symlinked into each workspace)

**graphify-out/**
- Purpose: Output directory for graphify analyses (if using `/graphify` skill)
- Generated: Yes (as-needed)
- Committed: No (in `.gitignore`)

## URL Routing & Path Organization

**Server Routes (NestJS Controllers):**

- `/api/trips` → TripsController (`server/src/nest/trips/trips.controller.ts`)
- `/api/trips/:id/assignments` → AssignmentsController
- `/api/trips/:id/places` → PlacesController
- `/api/auth/*` → AuthController
- `/api/weather` → WeatherController
- `/api/maps/*` → MapsController
- `/ws` → WebSocket endpoint
- `/uploads/*` → Static file serving (photos, avatars, covers)
- `/` → SPA fallback (index.html in production)

**Client Routes (React Router):**

- `/` → DashboardPage (list of trips)
- `/trips/:id/planner` → TripPlannerPage (main planner UI)
- `/trips/:id/shared` → SharedTripPage (guest view)
- `/admin` → AdminPage (admin settings)
- `/settings` → SettingsPage (user settings)
- `/atlas` → AtlasPage (travel journal, bucket list)
- `/vacay` → VacayPage (vacation day tracker)
- `/collections` → CollectionsPage (saved places collections)
- `/journey` → JourneyPage (journey index)
- `/journey/:id` → JourneyDetailPage
- `/login` → LoginPage
- `/register` → RegisterPage
- `/help` → HelpPage

## Module Organization

**Server NestJS Modules:**

Each domain gets a module with:
- `{domain}.module.ts` — declares controller, service, imports dependencies
- `{domain}.controller.ts` — HTTP routes, request validation, response formatting
- `{domain}.service.ts` — business logic, database queries, validation errors

Example: `server/src/nest/trips/`
```
trips/
├── trips.module.ts
├── trips.controller.ts
├── trips.service.ts
```

Modules imported into `server/src/nest/app.module.ts` for composition.

**Shared Schemas:**

Each domain gets a schema file:
- `{domain}.schema.ts` — Request and response Zod schemas

Example: `shared/src/trip/`
```
trip/
├── trip.schema.ts
```

All exported from `shared/src/index.ts` for both server and client consumption.

**Client Components:**

Organized by feature:
```
client/src/components/
├── Layout/                 # Global layout (header, nav, footer)
├── TripCard/              # Reusable trip preview
├── TripPlanner/           # Main planner subcomponents
├── DayPlanner/            # Day-level UI components
├── BackgroundTasks/       # Offline sync progress indicator
└── shared/                # Globally-reusable UI primitives (Button, Modal, etc.)
```
