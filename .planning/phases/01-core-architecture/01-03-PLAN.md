   const state = {
     tripId: null,
     messages: [], // { role: 'user'|'assistant', content }

   - window.trek.onContext((ctx) => { state.tripId = ctx.tripId; })
   - window.trek.invoke('/chat', { method: 'POST', body: JSON.stringify({ tripId, message }) })

   - Textarea auto-expand: input event → adjust height to scrollHeight (cap at 100px)
   - Textarea Enter key: keydown, if !shiftKey → preventDefault, call sendMessage()

6. **sendMessage() function:**
   - Trim input, validate not empty and not already waiting
   - Set waiting = true, disable inputs
   - Add user message to DOM (via addMessage('user', msg))
   - Call trek.invoke('/chat', ...) with tripId + message
   - Handle response: if error, show error toast via trek.notify('error', ...)
   - Add assistant message to DOM (via addMessage('assistant', response))
   - Clear input, reset waiting flag, restore focus

7. **addMessage(role, content) function:**
   - Create div with class "message {role}"
   - Set textContent to content (prevents XSS)
   - Append to #messages
   - Scroll to bottom: messagesEl.scrollTop = messagesEl.scrollHeight
   - Push to state.messages array

8. **Dark mode support:**
   - CSS variables handle automatically (trek:ui provides both light and dark values)
   - No media query needed (@prefers-color-scheme handled by tokens)

9. **Responsive layout:**
   - Desktop: sidebar (fixed width handled by host)
   - Tablet/mobile: flexbox adapts to 100% width
   - No hardcoded media queries; design kit handles responsiveness

10. **Accessibility (Phase 1 basics):**
    - Textarea has placeholder
    - Button has text label
    - Phase 3: add ARIA labels, live regions, keyboard shortcuts

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User Input ↔ DOM | Message content must be sanitized before display (no HTML injection) |
| Client ↔ LLM Response | Response from /chat must not be assumed trusted; display as text only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | HTML injection in message | High | Mitigate | Use textContent (not innerHTML) for message display. User input and LLM response treated as plain text, never HTML-parsed. |
| T-03-02 | Information Disclosure | Message content in UI state | Low | Accept | Messages stored in state.messages array (in-memory, ephemeral). Phase 2: persist to server via ctx.meta. No sensitive data in memory. |
| T-03-03 | Denial of Service | Large message flood | Low | Accept | Phase 1: no rate limiting (rely on LLM provider's rate limits). Phase 3: implement client-side throttling if needed. |

</threat_model>
