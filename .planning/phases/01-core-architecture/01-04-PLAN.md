   # AI Chatbot Plugin for Trek
   
   Conversational AI assistant for trip planning. Supports OpenAI, Anthropic, and local LLMs (Ollama, llama.cpp).
   
   ## Installation
   
   ```bash
   git clone [repo-url]
   cd ai-chatbot
   npm install
   ```
   
   ## Local Development
   
   ```bash
   npx trek-plugin-sdk dev
   ```
   
   Starts dev server at http://localhost:4317
   - Dashboard: view routes, logs
   - UI preview: /preview (with theme toggle)
   - Routes: directly callable via dashboard
   
   ## Plugin Setup
   
   1. Install in Trek admin panel (Plugins → Add → AI Assistant)
   2. Configure LLM provider:
      - Local: Ollama baseUrl, no key required
      - OpenAI: api key required
      - Anthropic: api key required
   3. MCP addon required (for Phase 2+ trip data access)
   4. Grant permissions: db:read:trips, db:meta, ws:broadcast:trip
   ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dev fixtures ↔ ctx mocking | Mock data should reflect production structure (to catch issues early) |
| Manual testing ↔ security | Permission denial tests catch escalation bugs before production |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Elevation of Privilege | Permission enforcement missed in dev | High | Mitigate | Permission denial test (remove permission, verify PERMISSION_DENIED error). Run before every release. |
| T-04-02 | Information Disclosure | Debug logs expose sensitive data | Medium | Mitigate | Review server logs during testing; verify no API keys, trip IDs, or user messages logged in full. Truncate to 100 chars if debugging needed. |
| T-04-03 | Denial of Service | Dev fixtures insufficient for scale test | Low | Accept | Phase 1: basic fixtures (1 trip, 1 user). Phase 4: load test with 1000+ messages, verify performance. |

</threat_model>
